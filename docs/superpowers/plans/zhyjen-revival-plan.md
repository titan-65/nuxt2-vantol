# ZhyJen Revival Plan

## Overview

ZhyJen should be relaunched as a youth-focused coding education brand that helps young people learn programming through simple, meaningful, and purpose-driven projects.

The original GitHub organization shows that the idea already existed around 2021 as an educational coding brand for young people. The new direction should modernize the brand, clean up the repositories, and develop a simple learning platform that teaches coding while encouraging creativity, discipline, service, and Christian values.

The platform should not feel overly religious or forced. Instead, it should be faith-informed, using Christian values as a guiding foundation for character, purpose, service, excellence, and responsible use of technology.

---

# 1. Refreshed Mission

## Mission Statement

**ZhyJen exists to help young people learn to code, build useful projects, and develop their God-given talents through creativity, problem-solving, and service.**

## Expanded Mission

ZhyJen is a beginner-friendly coding education platform for young people, especially young Christian youths, that teaches programming through simple hands-on web development activities.

The goal is not only to teach technical skills, but also to help students understand how coding can be used to create, serve, solve problems, communicate ideas, and build confidence.

## Core Message

**Learn to code. Build with purpose.**

---

# 2. Brand Positioning

ZhyJen should sit at the intersection of:

- Youth coding education
- Creativity
- Character development
- Christian values
- Digital skills
- Service-based learning

## Positioning Statement

**ZhyJen helps young creators learn programming through simple coding activities inspired by creativity, service, and Christian values.**

## What Makes ZhyJen Different

ZhyJen should not try to compete directly with large platforms like Codecademy, Khan Academy, or freeCodeCamp.

Instead, ZhyJen should be smaller, warmer, more guided, and more purpose-driven.

The unique angle is:

> ZhyJen teaches young people to code through meaningful projects that connect technical skills with purpose, creativity, service, and good character.

---

# 3. Target Audience

## Primary Audience

ZhyJen should focus mainly on young people between the ages of **10 and 18**.

This includes:

- Church youth groups
- Christian school students
- School coding clubs
- Homeschool groups
- Beginner web development learners
- Students interested in technology
- Young people who want to build websites, apps, and digital tools

## Secondary Audience

ZhyJen can also support adults who work with young people.

This includes:

- Parents
- Teachers
- Youth leaders
- Church media team leaders
- Sunday school leaders
- Coding club coordinators
- Mentors

These adults may not be expert programmers, so ZhyJen should provide clear, ready-to-use resources.

---

# 4. Platform Vision

ZhyJen should become a simple learning hub built around four main areas:

1. Learn
2. Build
3. Reflect
4. Share

---

## 4.1 Learn

This section should contain short beginner-friendly lessons.

Possible topics:

- HTML basics
- CSS basics
- JavaScript fundamentals
- Web design principles
- GitHub basics
- Publishing simple websites
- Problem-solving
- Debugging
- Digital responsibility
- Intro to web apps
- Intro to portfolios

The lessons should be simple, direct, and practical.

---

## 4.2 Build

This section should contain hands-on coding activities.

Students should learn by building small projects.

Examples:

- Personal profile card
- Bible verse display page
- Youth group event page
- Prayer request form mockup
- Kindness challenge tracker
- Scripture memory flashcards
- Habit tracker
- Church announcement page
- Gratitude journal interface
- Personal portfolio page

The goal is for students to finish each activity with something they can see, use, and improve.

---

## 4.3 Reflect

Each activity should end with a simple reflection section.

Reflection questions can include:

- What did you build?
- What problem does it solve?
- How could this help someone?
- What did you learn about patience?
- What did you learn about excellence?
- What did you learn about service?
- What would you improve next time?
- How can technology be used responsibly?

The reflection should not be long or heavy. It should simply help students connect coding with purpose and growth.

---

## 4.4 Share

Students should be encouraged to share their work.

Possible sharing options:

- GitHub Pages
- Screenshots
- Class presentation
- Church youth group showcase
- Student project gallery
- Monthly challenge submission
- Coding club portfolio

Later, ZhyJen could include a student showcase section.

---

# 5. Faith-Based Framing

ZhyJen should be faith-informed, but not overly preachy.

The goal is to connect coding with positive Christian values such as:

- Service
- Stewardship
- Excellence
- Patience
- Creativity
- Humility
- Encouragement
- Wisdom
- Responsibility
- Community

## Good Approach

Teach real coding skills first, then connect the activity to a value or reflection.

| Coding Skill | Value Connection |
|---|---|
| Debugging | Patience and perseverance |
| Clean code | Excellence and stewardship |
| Building websites | Communication and service |
| Forms | Listening to people’s needs |
| Team projects | Unity and humility |
| Version control | Growth over time |
| Accessibility | Caring for others |
| Documentation | Helping the next person |

## What to Avoid

Avoid making every project only about Bible verses or devotionals.

That could become repetitive.

Instead, ZhyJen should include a mix of:

- General youth projects
- Service-based projects
- Personal growth projects
- Church/community projects
- Faith-inspired projects
- Creative coding projects

This makes the platform more flexible and more useful.

# 8. Application Direction

ZhyJen should be built as a simple, beginner-friendly web application inside this monorepo.

The first application should prioritize:

- A clear landing page explaining the mission
- A lesson/activity browsing experience
- Simple project pages with instructions
- A warm, youth-friendly visual identity
- Content that can be edited in Markdown
- A structure that can grow into a student showcase later

Suggested technical direction:

- Use the monorepo's Vite+ workflow (`vp`)
- Prefer TanStack Start for an app-style learning platform
- Keep the first release content-first and lightweight
- Avoid over-engineering authentication, payments, or complex dashboards
- Build around Markdown-driven lessons and activities
